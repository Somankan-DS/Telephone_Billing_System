# TeleBill Pro — Reference Repository Evaluation & Architectural Audit

## 1. Executive Summary

As mandated by Section 3 of the Master Project Prompt, three open-source telecommunications and billing repositories were researched and evaluated prior to architectural finalization:
1. **Reference A:** `bishalogy/billing` — Traditional Telephone Billing System
2. **Reference B:** `digitallinx/vBilling` — FreeSWITCH-based VoIP Telecom Billing Engine
3. **Reference C:** `BillRun/system` — Enterprise Open-Source Telco BSS/OSS Platform

None of the reference repositories were copied directly. Instead, their conceptual architectures, billing logic, database schemas, and potential vulnerabilities were critically examined. This document details the concepts **adopted**, **modified**, and **rejected**, accompanied by engineering justifications.

## 3. Reference A: Telephone Billing System (`bishalogy/billing`)

### Architectural Summary
Reference A represents a foundational college-level telephone billing workflow written in procedural PHP with direct MySQL connectivity. It provides basic customer record storage, plan definitions, manual call detail entry, and bill calculation.

### Adopted Concepts
- **Core Domain Entities:** The tripartite relationship between **Subscriber**, **Tariff Plan**, and **Call Record** provided a clear conceptual model for telecom customer management.
- **Categorization of Telecom Calls:** The logical partition of calling destinations into `LOCAL`, `STD` (National Long Distance), and `ISD` (International Subscriber Dialing) was preserved as standard telecom domain terminology.

### Modified Concepts
- **Tariff Plan Flexibility:** In Reference A, call rates were often hardcoded directly into database triggers or PHP calculation scripts. TeleBill Pro made tariffs 100% data-driven and configurable via administrative APIs with independent rates for Local, STD, and ISD, along with customizable pulse durations.

### Rejected Concepts & Security Vulnerabilities
- ❌ **MD5 Password Hashing:** Reference A stored passwords using unsalted `md5($password)`. MD5 has been cryptographically broken for decades and is vulnerable to precomputed rainbow table attacks. TeleBill Pro strictly adopted **Bcrypt with Cost Factor 12** (~300ms compute wall).
- ❌ **SQL Injection Vulnerabilities:** Queries in Reference A concatenated unescaped `$_POST` strings directly into SQL queries (`"SELECT * FROM users WHERE user = '" . $user . "'"`). TeleBill Pro eliminated all raw string concatenation by using **Prisma ORM** with compile-time type validation and parameterized queries.
- ❌ **Binary Floating-Point Arithmetic:** Calculations utilized standard PHP `float` types, introducing IEEE-754 drift. TeleBill Pro enforces **Decimal.js** across all financial rating calculations.

## 4. Reference B: vBilling (`digitallinx/vBilling`)

### Architectural Summary
`vBilling` is a VoIP billing and customer management platform architected around the FreeSWITCH softswitch telephony engine. It listens to FreeSWITCH Event Socket Library (ESL) events, processes CDRs generated by SIP channels, and manages prepaid balances and postpaid limits.

### Adopted Concepts
- **Pulse-Based Rating Logic:** TeleBill Pro adopted vBilling's pulse rating model, where call durations are quantized into discrete billing increments (e.g., 60-second pulses or 1-second precision intervals) using ceiling division:
  $$\text{Pulses} = \left\lceil \frac{\text{Duration}}{\text{Pulse Interval}} \right\rceil$$
- **Prepaid vs Postpaid Dual Lifecycles:** vBilling's model of deducting from an active wallet balance for prepaid subscribers while tracking credit limits and rolling over arrears for postpaid accounts was directly incorporated into TeleBill Pro.

### Modified Concepts
- **Traffic Ingestion Mechanism:** Rather than binding directly to FreeSWITCH socket events, TeleBill Pro implemented a **Streaming CSV Ingestion Engine** and an integrated **Poisson Traffic Simulator**. This allows full simulation and demonstration of real-world call loads without requiring complex telephony PBX hardware or softswitches.

### Rejected Concepts & Rationale
- ❌ **FreeSWITCH Telecom Infrastructure Dependency:** vBilling requires a functional FreeSWITCH Linux daemon, SIP softphones, and audio codecs. Requiring FreeSWITCH for a college software engineering project creates extreme deployment friction and dependency brittleness without adding academic value to core billing algorithms.
- ❌ **Outdated Framework Dependencies:** vBilling relies on legacy PHP extensions (PDO MySQL, PECL libraries) that fail to build on modern PHP 8.x runtimes.

## 5. Reference C: BillRun (`BillRun/system`)

### Architectural Summary
`BillRun` is an enterprise-grade telecom billing and customer management platform designed for Tier-1 and Tier-2 telecommunications carriers. It processes billions of events via MongoDB, complex line-rating pipelines, multi-currency conversions, and roaming settlement (TAP3/Diameter).

### Adopted Concepts
- **Free Allowance Quota Buckets:** BillRun's concept of a `FreeAllowanceBucket`—tracking inclusive minutes per cycle that are decremented prior to assessing monetary charges—was adopted and formalized into TeleBill Pro's database schema.
- **Statutory Tax Separation:** BillRun isolates statutory taxation (e.g., 18% GST) to fresh cycle charges, ensuring arrears brought forward from past delinquent cycles remain uncompounded.
- **Audit Logging:** Administrative changes to customers, tariff plans, and financial operations are recorded in an append-only `AuditLog` table.

### Modified Concepts
- **Predictive Analytics:** While BillRun relies on batch business intelligence exports to external data lakes, TeleBill Pro embedded an **Intra-Cycle Hybrid Predictive Bill Engine** directly into the customer portal, providing subscribers with an explainable AI narrative of their anticipated month-end bill.

### Rejected Concepts & Rationale
- ❌ **NoSQL Schema Overhead:** BillRun utilizes deeply nested MongoDB documents. While suitable for multi-terabyte telecommunication data lakes, it introduces eventual consistency complications. TeleBill Pro selected an ACID-compliant relational schema via **SQLite WAL mode**, guaranteeing transactional integrity for billing runs and payments.
- ❌ **Extreme Overengineering:** BillRun includes thousands of enterprise modules (e.g., roaming clearinghouses, wholesale interconnect billing, complex CRM integrations) that obscure core billing engineering for an academic evaluation.

## 6. Synthesis: TeleBill Pro's Original Engineering Contributions

By synthesizing the lessons of References A, B, and C, TeleBill Pro achieved:
1. **Deterministic Fixed-Point Decimal Mathematics:** Eliminates the financial drift of Reference A.
2. **Infrastructure-Independent Telephony Simulation:** Retains the pulse rating and prepaid enforcement of Reference B without requiring FreeSWITCH.
3. **Enterprise Quota Buckets & Tax Isolation:** Implements the robust billing logic of Reference C in a clean, explainable, and demonstrable modular monolith.
4. **Idempotent SHA-256 Deduplication:** Ensures zero duplicate billing across all ingestion streams.
5. **Intra-Cycle Predictive Intelligence:** Introduces transparent, explainable bill forecasting for subscribers.
